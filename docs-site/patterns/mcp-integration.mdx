You have an MCP server with tool handlers. You want governance -- visibility into what tools your AI agents are calling, and the ability to block, rate-limit, or require approval before execution.

hiitl's `evaluate()` call wraps your existing tool handlers. No new framework, no architectural changes.

## Before and after

<CodeGroup>

```python Before (unprotected)
@server.call_tool()
async def handle_tool(name: str, arguments: dict):
    if name == "send_email":
        return await send_email(arguments["to"], arguments["subject"], arguments["body"])
```

```python After (protected by hiitl)
@server.call_tool()
async def handle_tool(name: str, arguments: dict):
    result = hiitl.evaluate(name, parameters=arguments)
    if not result.ok:
        return CallToolResult(isError=True, content=[
            TextContent(type="text", text=f"Blocked: {result.reason_codes}")
        ])

    if name == "send_email":
        return await send_email(arguments["to"], arguments["subject"], arguments["body"])
```

</CodeGroup>

Every tool call now passes through the control point before executing.

## Step 2: Initialize

Add hiitl initialization alongside your existing MCP server setup. The snippets use that server's installed MCP library and application handlers; Python replies below use `CallToolResult` and `TextContent` from `mcp.types`.

<CodeGroup>

```python Python
from hiitl import HIITL
from mcp.server import Server
from mcp.types import CallToolResult, TextContent

server = Server("my-mcp-server")

hiitl = HIITL(
    environment="dev",
    agent_id="my-mcp-server",
    org_id="org_devlocal0000000000",
    policy_path="./policy.yaml",
    mode="RESPECT_POLICY",
)
```

```typescript TypeScript
import { HIITL } from '@hiitl/sdk';
import { Server } from '@modelcontextprotocol/sdk/server/index.js';

const server = new Server(
  { name: 'my-mcp-server', version: '1.0.0' },
  { capabilities: { tools: {} } }
);

const hiitl = new HIITL({
  environment: 'dev',
  agent_id: 'my-mcp-server',
  org_id: 'org_devlocal0000000000',
  policy_path: './policy.yaml',
  mode: 'RESPECT_POLICY',
});
```

</CodeGroup>

No API key needed for local mode. The SDK runs evaluation entirely in-process. `mode="RESPECT_POLICY"` enforces the policy; under the default mode, `OBSERVE_ALL`, a decision other than `ALLOW` or `SANDBOX` comes back as `OBSERVE`, with `allowed` true and the policy's decision in `would_be`.

## Step 3: Wrap tool handlers

Add `evaluate()` at the top of your tool handler.

<CodeGroup>

```python Python
@server.call_tool()
async def handle_tool(name: str, arguments: dict):
    result = hiitl.evaluate(name, parameters=arguments)

    if not result.ok:
        return CallToolResult(isError=True, content=[
            TextContent(type="text", text=f"Action blocked by policy: {result.reason_codes}")
        ])

    if name == "send_email":
        return await send_email(arguments["to"], arguments["subject"], arguments["body"])
    elif name == "query_database":
        return await run_query(arguments["sql"])
    elif name == "process_payment":
        return await charge_card(arguments["amount"], arguments["currency"])
```

```typescript TypeScript
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;

  const result = await hiitl.evaluate({ action: name, parameters: args ?? {} });

  if (!result.allowed) {
    return {
      isError: true,
      content: [{ type: 'text', text: `Action blocked: ${result.reason_codes}` }],
    };
  }

  if (name === 'send_email') {
    return await sendEmail(args.to, args.subject, args.body);
  }
});
```

</CodeGroup>

### What `evaluate()` gives you

| Property | Type | Description |
|----------|------|-------------|
| `result.ok` | bool | Safe to proceed (the decision's `allowed`) |
| `result.blocked` | bool | Denied by policy |
| `result.needs_approval` | bool | Requires human review |
| `result.reason_codes` | list | Why the decision was made |
| `result.remediation` | object | Guidance on what to do |

These are the Python properties. The TypeScript Decision has `result.allowed`, `result.decision`, `result.reason_codes` and `result.remediation`.

## Step 4: Add a policy

Create `policy.yaml`:

```yaml
policy_set:
  name: "mcp-server-policy"
  version: "v1.0.0"
  description: "Controls on the MCP server's tools"
  scope:
    org_id: "org_devlocal0000000000"
    environment: "dev"

  rules:
    - name: "block-large-payments"
      description: "Block payments over $500"
      priority: 100
      conditions:
        all_of:
          - field: "action"
            operator: "equals"
            value: "process_payment"
          - field: "parameters.amount"
            operator: "greater_than"
            value: 500
      decision: "BLOCK"
      reason_code: "PAYMENT_TOO_HIGH"

    - name: "allow-all"
      description: "Allow every other tool call"
      priority: 1
      conditions:
        all_of:
          - field: "action"
            operator: "exists"
            value: true
      decision: "ALLOW"
      reason_code: "DEFAULT_ALLOW"
```

## Step 5: Run it

Start your MCP server as usual. Evaluations happen inline. A local policy check needs no hosted hiitl service; configured sync routes and the tool itself may make network calls.

## Handling different decisions

<CodeGroup>

```python Python
@server.call_tool()
async def handle_tool(name: str, arguments: dict):
    result = hiitl.evaluate(name, parameters=arguments)

    if result.ok:
        return await execute_tool(name, arguments)

    if result.needs_approval:
        return CallToolResult(isError=True, content=[
            TextContent(type="text", text=f"This action requires approval. Action ID: {result.action_id}")
        ])

    if result.blocked:
        msg = f"Blocked: {result.reason_codes}"
        if result.remediation:
            msg += f"\nSuggestion: {result.remediation.suggestion}"
        return CallToolResult(isError=True, content=[TextContent(type="text", text=msg)])

    return CallToolResult(isError=True, content=[
        TextContent(type="text", text=f"Action not allowed: {result.reason_codes}")
    ])
```

```typescript TypeScript
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;
  const result = await hiitl.evaluate({ action: name, parameters: args ?? {} });

  if (result.allowed) {
    return await executeTool(name, args);
  }

  if (['REQUIRE_APPROVAL', 'PAUSE', 'ESCALATE'].includes(result.decision)) {
    return {
      isError: true,
      content: [{ type: 'text', text: `Requires approval. ID: ${result.action_id}` }],
    };
  }

  if (['BLOCK', 'KILL_SWITCH', 'RATE_LIMIT'].includes(result.decision)) {
    const suggestion = result.remediation?.suggestion
      ? `\nSuggestion: ${result.remediation.suggestion}`
      : '';
    return {
      isError: true,
      content: [{ type: 'text', text: `Blocked: ${result.reason_codes}${suggestion}` }],
    };
  }

  return {
    isError: true,
    content: [{ type: 'text', text: `Not allowed: ${result.reason_codes}` }],
  };
});
```

</CodeGroup>

## Moving to production

Connect to the hosted service by adding an API key:

```python
import os

hiitl = HIITL(
    api_key=os.getenv("HIITL_API_KEY"),
    server_url=os.getenv("HIITL_SERVER_URL"),
    environment="prod",
    agent_id="governed-mcp-server",
    mode="RESPECT_POLICY",
)
```

In Python, an `api_key` (with or without `server_url`) runs the SDK in hybrid mode: evaluation stays in-process, and policies (with their kill-switch rules) and audit records sync with the hosted service. TypeScript uses the same table: an `api_key` enables hybrid mode, with `server_url` as its sync target when supplied. Hosted evaluation requires `evaluation: 'remote'`, `server_url` and the API key's `signature_key`.

The `evaluate()` calls stay exactly the same. Only the initialization changes.

## Troubleshooting

**`evaluate()` always returns ok** -- The SDK is running in its default mode, `OBSERVE_ALL`, which reports a policy's decision in `would_be` without stopping the call. Create a `policy.yaml`, pass its path to HIITL, and pass `mode="RESPECT_POLICY"`.

**Action name mismatch** -- The `name` in `evaluate(name, parameters=arguments)` must match the `action` value in your policy conditions.

**Arguments structure** -- `evaluate()` passes `arguments` as parameters. Policy conditions reference them as `parameters.field_name`.
