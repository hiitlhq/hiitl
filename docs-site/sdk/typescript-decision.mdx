## Overview

Every `evaluate()` call returns a `Decision` object. It contains the evaluation outcome, timing metadata, matched rules, and guidance for what to do next.

```typescript
const decision = await hiitl.evaluate({ action: 'process_payment', parameters: { amount: 500 } });

if (decision.allowed) {
  processPayment();
}
```

## Fields

### Core fields

<ResponseField name="decision" type="DecisionType" required>
  The decision type. One of:

  | Value | `allowed` | Meaning |
  |-------|-----------|---------|
  | `"ALLOW"` | `true` | Action is permitted |
  | `"OBSERVE"` | `true` | Action was logged but not enforced (OBSERVE mode) |
  | `"BLOCK"` | `false` | Denied by policy |
  | `"PAUSE"` | `false` | Paused pending external resolution |
  | `"REQUIRE_APPROVAL"` | `false` | Needs human review |
  | `"SANDBOX"` | `true` | Allowed in isolated/sandbox environment |
  | `"RATE_LIMIT"` | `false` | Rate limit exceeded |
  | `"KILL_SWITCH"` | `false` | Emergency stop active |
  | `"ESCALATE"` | `false` | Escalated for review |
  | `"ROUTE"` | `false` | Waiting on a sync route's answer: the route was not asked or did not answer |
  | `"SIGNATURE_INVALID"` | `false` | The envelope's signature does not verify; it was not evaluated |
  | `"VALIDATION_ERROR"` | `false` | The envelope is not one the control point admits (hosted mode) |
  | `"POLICY_ERROR"` | `false` | The policy could not be loaded, read or evaluated |
  | `"CONTROL_PLANE_UNAVAILABLE"` | `false` | The hosted service could not be reached (hosted mode), with `metadata`; `true` only under `fail_mode: 'FAIL_OPEN'` |
</ResponseField>

<ResponseField name="allowed" type="boolean" required>
  Whether the action is permitted. `true` for `ALLOW`, `OBSERVE`, and `SANDBOX`. `false` for everything else.
</ResponseField>

<ResponseField name="reason_codes" type="string[]" required>
  List of reason codes explaining the decision. Comes from matched policy rules (e.g., `["PAYMENT_TOO_HIGH"]`) or system codes (e.g., `["NO_MATCHING_RULE"]`, `["OBSERVED"]`, `["RATE_LIMIT_EXCEEDED"]`).
</ResponseField>

<ResponseField name="action_id" type="string" required>
  The auto-generated action ID for this evaluation. Format: `act_` followed by 20+ alphanumeric characters.
</ResponseField>

<ResponseField name="policy_version" type="string" required>
  Version of the policy set used for evaluation. Enables debugging and replay.
</ResponseField>

### Timing

<ResponseField name="timing" type="Timing" required>
  Performance metadata. Every decision includes timing so you can verify latency.

  | Field | Type | Description |
  |-------|------|-------------|
  | `timing.ingest_ms` | `number` | Locally: from the call to `evaluate()`: admitting its input, building the envelope (and checking its signature, when a `signature_key` is set), and the evaluator's read of the envelope and policy. Hosted: time the service spent loading the policy and writing the audit record |
  | `timing.evaluation_ms` | `number` | Time to evaluate the policy |
  | `timing.total_ms` | `number` | Locally: the evaluator's time. Hosted: the service's time for the request. Network time is not included |

  ```typescript
  console.log(`Evaluated in ${decision.timing.evaluation_ms.toFixed(2)}ms`);
  // Evaluated in 0.34ms
  ```
</ResponseField>

### Observe mode fields

<ResponseField name="would_be" type="string | undefined">
  When `decision` is `"OBSERVE"`, this shows what the decision *would have been* under enforcement. For example, `"BLOCK"` or `"REQUIRE_APPROVAL"`. `OBSERVE` comes only from the `OBSERVE_ALL` mode.
</ResponseField>

<ResponseField name="would_be_reason_codes" type="string[] | undefined">
  When `decision` is `"OBSERVE"`, the reason codes that would have applied under enforcement.
</ResponseField>

### Policy details

<ResponseField name="matched_rules" type="MatchedRule[] | undefined">
  Rules that matched during evaluation. Each entry has `rule_name`, `policy_set`, and `priority`.
</ResponseField>

<ResponseField name="envelope_hash" type="string | undefined">
  Hosted mode only. SHA-256 hash of the envelope the service evaluated. The `Decision` type does not declare it; read it as `(decision as Decision & { envelope_hash?: string }).envelope_hash`.
</ResponseField>

### Escalation fields

<ResponseField name="resume_token" type="string | undefined">
  Token to correlate an escalation decision with a reviewer's response. Present when `decision` is `REQUIRE_APPROVAL`, `PAUSE`, or `ESCALATE`.
</ResponseField>

<ResponseField name="route_ref" type="string | undefined">
  The route the matched rule names. Present when `decision` is `REQUIRE_APPROVAL`, `PAUSE`, `ESCALATE` or `ROUTE`. The SDK uses it to resolve `escalation_context`.
</ResponseField>

<ResponseField name="escalation_context" type="Record<string, unknown> | undefined">
  Resolved escalation routing details. Populated by the SDK when it has the named route loaded (`routes_path`). Contains the route's `endpoint` and `protocol`, its SLA `timeout` and `timeout_action`, the reviewer's `decision_options`, the `fields` the reviewer sees, the risk framing's `severity` and `summary`, the `escalation_ladder`, and the `token_field` the resume token travels in, as the route defines them; a key the route leaves unset is absent.
</ResponseField>

### Rate limit fields

<ResponseField name="rate_limit" type="RateLimit | undefined">
  The counter state of a rate-limit window. On a `RATE_LIMIT`, or an `OBSERVE` whose `would_be` is `RATE_LIMIT`, it is the exceeded window. On an `ALLOW` the limiter counted, it is the window with the least headroom left, this call included; on a tie, the first listed. Contains `scope`, `window`, `limit`, `current` count, and `reset_at` timestamp. Absent when no windowed rule matched.

  ```typescript
  if (decision.decision === 'RATE_LIMIT' && decision.rate_limit) {
    const rl = decision.rate_limit;
    console.log(`Limit: ${rl.current}/${rl.limit} in ${rl.window}`);
    console.log(`Resets at: ${rl.reset_at}`);
  }
  ```
</ResponseField>

### Error and remediation

<ResponseField name="error" type="ErrorDetail | undefined">
  Present when ECP itself failed (not when policy enforcement blocked an action). Contains `code` (machine-readable) and `message` (human-readable with guidance). On an error decision (`SIGNATURE_INVALID`, `VALIDATION_ERROR`, `POLICY_ERROR`, `CONTROL_PLANE_UNAVAILABLE`) `code` is the decision and the cause is the reason code. When the SDK's rate limiter fails, the decision is `BLOCK` with `RATE_LIMIT_SERVICE_ERROR`; when the audit record cannot be written, `BLOCK` with `AUDIT_WRITE_FAILED`. Under `OBSERVE_ALL` a failed limiter's block is observed, and `error` is kept; a failed audit write is never observed. The message never carries the caught exception's text: the cause is logged.

  ```typescript
  if (decision.error) {
    console.error(`ECP error: [${decision.error.code}] ${decision.error.message}`);
  }
  ```
</ResponseField>

<ResponseField name="remediation" type="Remediation | undefined">
  Present when the binding rule defines remediation and its decision is not allowed, for example `BLOCK`. Contains `message`, `suggestion`, `type`, and optional `details`, as the rule writes them, except a detail that states a fact of the call, which is computed from the call: `blocked_fields` written as `{ref, filter}`, a threshold's `current_value` and a temporal `current_time` (see [Remediation](/concepts/policies#remediation)). A `RATE_LIMIT` from a windowed rule carries that rule's remediation; a `rate_limit` remediation's details are the window's counter state. Mutually exclusive with `error`.

  ```typescript
  if (decision.remediation) {
    console.log(`Why: ${decision.remediation.message}`);
    console.log(`Fix: ${decision.remediation.suggestion}`);
  }
  ```
</ResponseField>

<Note>
  `error` and `remediation` are mutually exclusive. `error` means ECP failed. `remediation` means ECP worked and intentionally enforced a policy.
</Note>

### Staged and rate-limit rules

<ResponseField name="staged_observations" type="StagedObservation[]" required>
  What each matching staged rule would have decided. Each entry has `rule_name`, `policy_set`, `priority`, `would_be_decision`, `would_be_reason_codes` and `would_be_binding`. Always an array; empty when no staged rule matched.
</ResponseField>

<ResponseField name="rate_limit_rules" type="RateLimitRule[]" required>
  The matching rate-limit rules with a window. Each entry has `rule_name`, `policy_set`, `priority`, `reason_code`, `limit`, `window_seconds`, `scope` and, when the rule writes one, `remediation`. They do not bind. When the decision is `ALLOW`, the SDK reads every window before it counts any, so a call one window refuses is counted in none. Always an array.
</ResponseField>

### Sync route fields

<ResponseField name="enrichment" type="Record<string, Record<string, unknown>> | undefined">
  The sync-route answers that re-entered evaluation, as `{ route: { field: value } }`.
</ResponseField>

<ResponseField name="routes" type="RouteAsked[] | undefined">
  Each sync route asked. Each entry has `rule_name`, `route`, `outcome` (`'answered'`, `'unanswered'` or `'failed_open'`), `fields` and `error`.
</ResponseField>

### Cache state

<ResponseField name="cache_status" type="'synced' | 'from_disk' | 'empty' | null | undefined">
  Hybrid mode only. The state of the SDK's policy cache: `'synced'` (synced in this process), `'from_disk'` (loaded from the disk cache, not yet synced) or `'empty'` (no policies yet).
</ResponseField>

### Outage

<ResponseField name="metadata" type="DecisionMetadata | undefined">
  Hosted mode only, present on `CONTROL_PLANE_UNAVAILABLE`. `fail_mode` is the client's `fail_mode` setting. Under `'FAIL_CLOSED'`, the default, the action was not evaluated and is not allowed; under `'FAIL_OPEN'`, opt-in, `allowed` is `true` and `error.message` is the warning, logged and recorded. `circuit_breaker_state` is the hosted client's circuit breaker after the call: `'closed'`, `'open'` or `'half_open'`. Once it opens, calls fail fast with `CIRCUIT_BREAKER_OPEN` and are not sent until its reset interval passes. The reason code names the cause: `CONTROL_PLANE_TIMEOUT`, `CONTROL_PLANE_UNREACHABLE` or `CIRCUIT_BREAKER_OPEN`.
</ResponseField>

## Decision type constants

You can use the `DecisionType` enum for type-safe comparisons:

```typescript
import { DecisionType } from '@hiitl/core';

if (decision.decision === DecisionType.BLOCK) {
  // ...
}

if (decision.decision === DecisionType.REQUIRE_APPROVAL) {
  // ...
}
```

## Common patterns

### Basic allow/deny

```typescript
const decision = await hiitl.evaluate({
  action: 'send_email',
  parameters: {
    to: 'user@example.com',
    subject: 'Order confirmation',
  },
});

if (decision.allowed) {
  sendEmail();
} else {
  handleDenial(decision.reason_codes);
}
```

### Full decision routing

```typescript
const decision = await hiitl.evaluate({
  action: 'process_payment',
  parameters: { amount: 5000 },
});

switch (decision.decision) {
  case 'ALLOW':
    executePayment();
    break;

  case 'BLOCK':
  case 'KILL_SWITCH':
    logBlocked(decision.reason_codes);
    if (decision.remediation) {
      notifyUser(decision.remediation.suggestion);
    }
    break;

  case 'REQUIRE_APPROVAL':
    submitForReview({
      action: 'process_payment',
      resumeToken: decision.resume_token,
    });
    break;

  case 'RATE_LIMIT':
    if (decision.rate_limit) {
      scheduleRetry(decision.rate_limit.reset_at);
    }
    break;

  case 'OBSERVE':
    // Not enforced — proceed but log
    logObservation(decision.would_be);
    executePayment();
    break;

  case 'SANDBOX':
    executeInSandbox();
    break;
}
```

### Checking decision categories

Unlike the Python SDK which provides convenience properties (`.ok`, `.blocked`, `.needs_approval`, `.observed`), the TypeScript SDK uses plain object fields. Here are equivalent helper patterns:

```typescript
// Check if allowed (equivalent to Python's .ok)
if (decision.allowed) {
  // ALLOW, OBSERVE, or SANDBOX
}

// Check if blocked
const isBlocked = !decision.allowed && ['BLOCK', 'KILL_SWITCH', 'RATE_LIMIT'].includes(decision.decision);

// Check if needs approval
const needsApproval = ['REQUIRE_APPROVAL', 'PAUSE', 'ESCALATE'].includes(decision.decision);

// Check if observed
const isObserved = decision.decision === 'OBSERVE';
```

### Logging decision details

```typescript
const decision = await hiitl.evaluate({
  action: 'delete_records',
  parameters: { table: 'users' },
});

console.log(`Decision: ${decision.decision}`);
console.log(`Allowed: ${decision.allowed}`);
console.log(`Reasons: ${decision.reason_codes.join(', ')}`);
console.log(`Policy: ${decision.policy_version}`);
console.log(`Latency: ${decision.timing.total_ms.toFixed(2)}ms`);

if (decision.matched_rules) {
  for (const rule of decision.matched_rules) {
    console.log(`  Matched: ${rule.rule_name} (priority ${rule.priority})`);
  }
}
```

## TypeScript types

`@hiitl/core` exports these Decision-related types:

```typescript
import type {
  Decision,
  MatchedRule,
  Remediation,
  StagedObservation,
  RateLimitRule,
} from '@hiitl/core';
```

Derive the others from `Decision`:

```typescript
type Timing = Decision['timing'];
type RateLimit = NonNullable<Decision['rate_limit']>;
type ErrorDetail = NonNullable<Decision['error']>;
```
