## Constructor

```python
HIITL(**kwargs)
```

All parameters are keyword-only. `HIITL()` with no arguments works in local OBSERVE mode.

## Parameters

### Identity

<ParamField path="agent_id" type="str" default='"default"'>
  Agent identifier. Included in every envelope and used for per-agent rate limiting.
</ParamField>

<ParamField path="environment" type="str" default='"dev"'>
  Execution environment. One of: `"dev"`, `"stage"`, `"prod"`. Controls environment isolation for policies, counters, and audit.
</ParamField>

<ParamField path="org_id" type="str" default='"org_devlocal0000000000"'>
  Organization ID. Must match the envelope's `org_id` pattern, `^org_[a-zA-Z0-9]{16,}$`. The default is a dev-local placeholder.
</ParamField>

### Policy mode

<ParamField path="mode" type="str" default='"OBSERVE_ALL"'>
  Policy evaluation mode.

  | Mode | Behavior |
  |------|----------|
  | `"OBSERVE_ALL"` | All actions are allowed. Decisions are logged with `would_be` fields showing what enforcement would do. |
  | `"RESPECT_POLICY"` | Policy rules are enforced. Actions can be blocked, require approval, etc. |
</ParamField>

### Local evaluation

<ParamField path="policy_path" type="str | None" default="None">
  Path to a policy file (JSON or YAML). Required when `mode="RESPECT_POLICY"` in local mode. Optional in OBSERVE_ALL mode (uses empty policy set).
</ParamField>

<ParamField path="audit_db_path" type="str" default='"./hiitl_audit.db"'>
  Path to the SQLite audit database. Created automatically if it does not exist. All evaluated actions are recorded here.
</ParamField>

<ParamField path="redact_fields" type="list[str] | None" default="None">
  Envelope fields this client's audit store records as `"[REDACTED]"`. Each is a dotted path to a member of one of the envelope's objects, such as `"parameters.account_number"` or `"target.email"`; a path through an array applies to every item. Evaluation sees the call whole. The record is redacted after the envelope is signed and its `envelope_hash` taken, and before the row's content hash, so the content hash covers the row as stored. A remediation that states the call's value at a declared field stores the marker too. In hybrid mode the client also applies the organization's own list (`PUT /v1/redaction-policy`), pulled with its policies, at every write, and the row is uploaded already redacted. In hosted mode (`evaluation="remote"`) the declaration applies to the records the client holds while the service is unreachable (`fail_mode`). A top-level field (`org_id`, `action`) raises `ConfigurationError`. A declared path the call does not carry is named in the record's `redaction` member, `{"absent": [...]}`, never skipped silently.
</ParamField>

<ParamField path="recorded_parameters" type="dict[str, list[str]] | None" default="None">
  `{action: [parameter names]}`. When set, the store records every other member of `parameters` by name, with its value as `"hmac-sha256:"` and the HMAC-SHA256 of its canonical form; `{}` hashes every parameter. The key is the store's: made at its first start beside the audit file (`<audit_db_path>.value_hash.key`, mode 0600), never synced or recorded. A key file of another length fails the start. The MCP gateway always sets this from its `recorded_arguments`.
</ParamField>

<ParamField path="enable_rate_limiting" type="bool" default="True">
  Whether to enforce rate limits defined in policy metadata.
</ParamField>

<ParamField path="routes_path" type="str | None" default="None">
  Path to a directory containing route configuration files (YAML/JSON). A `ROUTE` decision asks the route its rule names and evaluates again with the answer; for `REQUIRE_APPROVAL`, `PAUSE` and `ESCALATE` the named route's `escalation_context` is attached to the decision and nothing is sent.
</ParamField>

<ParamField path="signature_key" type="str | None" default="None">
  Your API key's signing secret, shown once when the key is created. When set, every envelope is signed and the SDK checks the signature before it evaluates; the signature is included in the audit record. When not set, the signature is 64 zeros. Hosted evaluation needs it: the service evaluates only a signed envelope.
</ParamField>

<ParamField path="dedup_window_seconds" type="int" default="86400">
  The dedup window. A call whose `idempotency_key` the audit store already holds, for an envelope timestamped within this many seconds of the new one, returns the first decision and writes no record. Past the window, the key names a new action with its own record.
</ParamField>

### Hosted evaluation

<ParamField path="api_key" type="str | None" default="None">
  API key for server authentication (Bearer token). Providing an API key changes the deployment mode.
</ParamField>

<ParamField path="server_url" type="str | None" default="None">
  Service URL (e.g., `"https://api.hiitl.com"`). Used with `api_key` and `evaluation="remote"` for hosted mode, and as the sync target in hybrid mode.
</ParamField>

<ParamField path="timeout" type="float" default="5.0">
  HTTP request timeout in seconds (hosted mode only). Range: 0.1-30; a value outside it raises `ConfigurationError` naming the range.
</ParamField>

<ParamField path="max_retries" type="int" default="3">
  Maximum retry attempts on transient failures (hosted mode only). Range: 0-10; a value outside it raises `ConfigurationError` naming the range.
</ParamField>

<ParamField path="fail_mode" type="str" default='"FAIL_CLOSED"'>
  What a hosted outage answers: the service unreachable, timing out, answering with a server error, or its circuit breaker open. `"FAIL_CLOSED"` answers with the action not allowed (`CONTROL_PLANE_UNAVAILABLE`, its cause in `reason_codes`); `"FAIL_OPEN"`, opt-in, allows it without evaluation and logs a warning. Either way the call is recorded in the local store at `audit_db_path`, under this client's `redact_fields`, and the records are sent to the service before the next call once it answers; no call, and so no record, is sent while the breaker is open. Any other value raises `ConfigurationError` naming the two.
</ParamField>

### Where evaluation happens

<ParamField path="evaluation" type="str" default="\"local\"">
  `"local"` evaluates in-process (local mode without `api_key`, hybrid mode with one). `"remote"` sends every evaluation to the service and requires `api_key` and `server_url` (hosted mode). Any other value is refused with a `ConfigurationError` naming the valid ones.
</ParamField>

<ParamField path="sync" type="bool" default="True">
  Enable sync when `api_key` is provided. Set to `False` to force pure local mode (the key is kept but nothing connects).
</ParamField>

### Telemetry

<ParamField path="telemetry_level" type="str" default='"standard"'>
  What the hybrid client's usage telemetry sends: `"full"`, `"standard"`, `"minimal"`, or `"off"`, which collects and sends nothing. Read from `HIITL_TELEMETRY_LEVEL` when not given. Any other value raises `ConfigurationError` naming the four. What each level sends is on [Data handling](/security/data-handling). Local and hosted modes send no telemetry.
</ParamField>

The collector's other settings are `SyncConfig`'s, each read from its `HIITL_TELEMETRY_*` variable when not given, and a value outside its range raises `ConfigurationError` naming the range:

| Setting | Variable | Default | Range |
|---------|----------|---------|-------|
| `telemetry_sync_interval` | `HIITL_TELEMETRY_INTERVAL` | 60 (seconds) | 5-3600 |
| `telemetry_buffer_size` | `HIITL_TELEMETRY_BUFFER_SIZE` | 60 (records) | 10-1000 |
| `telemetry_sample_rate` | `HIITL_TELEMETRY_SAMPLE_RATE` | 1.0 | 0-1: the fraction of evaluations whose parameter and target details are counted |
| `telemetry_parameter_tools` | `HIITL_TELEMETRY_PARAMETER_TOOLS` (a JSON list) | none | the actions whose parameters are counted |

## Deployment modes

The deployment mode is derived from `api_key`, `evaluation` and `sync`, whether passed to the constructor or read from their `HIITL_*` variables. You do not set it directly.

<Tabs>
  <Tab title="Local">
    **No `api_key`** — evaluation runs entirely in-process.

    ```python
    # Zero-config: observe everything, block nothing
    hiitl = HIITL()

    # With a policy: enforce rules locally
    hiitl = HIITL(
        agent_id="payment-agent",
        policy_path="./policy.yaml",
        mode="RESPECT_POLICY",
    )
    ```

    Local mode uses the embedded Python evaluator, writes to a local SQLite audit database, and requires zero infrastructure.
  </Tab>

  <Tab title="Hosted">
    **`api_key` + `server_url` + `evaluation="remote"`** — evaluation is sent to the service.

    ```python
    hiitl = HIITL(
        agent_id="payment-agent",
        org_id="org_mycompany123456789",
        api_key="sk_live_abc123...",
        server_url="https://api.hiitl.com",
        evaluation="remote",
        signature_key="...",  # the API key's signing secret, shown when the key was created
        environment="prod",
        mode="RESPECT_POLICY",
    )
    ```

    Hosted mode sends envelopes to the server for evaluation. The server manages policies, audit, rate limiting, and shared counters.
  </Tab>

  <Tab title="Hybrid">
    **`api_key` without `evaluation="remote"`** — local evaluation with policies synced from the hosted service (`server_url` names the service; the default is hiitl's).

    ```python
    hiitl = HIITL(
        agent_id="payment-agent",
        api_key="sk_live_abc123...",
        policy_path="./policy.yaml",
        mode="RESPECT_POLICY",
    )
    ```

    Hybrid mode evaluates locally using the embedded evaluator and syncs policies from the hosted service, uploading audit records in batches; a disk cache keeps it deciding when the service is unreachable. Routes and kill switches are downloaded but not yet applied; the client asks only the routes in its own `routes_path`. `policy_path` is the fallback policy when there is no cache; `cold_start_behavior="fail-closed"` makes the constructor refuse to start un-policied.
  </Tab>
</Tabs>

### Auto-detection rules

| `api_key` | `server_url` | `evaluation` | `sync` | Mode |
|-----------|--------------|--------------|--------|------|
| absent | absent | `"local"` (default) | -- | **local** |
| present | absent | `"local"` (default) | `True` (default) | **hybrid** (the default service) |
| present | present | `"local"` (default) | `True` (default) | **hybrid** (syncs with `server_url`) |
| present | absent | `"local"` (default) | `False` | **local** (key stored) |
| present | present | `"remote"` | -- | **hosted** |
| absent | present | `"remote"` | -- | **local** (no key, nothing connects) |
| present | absent | `"remote"` | -- | `ConfigurationError`: `server_url` is required |

The TypeScript SDK derives the mode from the same arguments by the same table.

## Environment variables

Every setting below can come from its `HIITL_` prefixed environment variable. An argument passed to `HIITL()` takes precedence, then the variable, then the default; `server_url` and `cache_dir` passed as arguments apply over a given `sync_config`. The mode is decided from the resolved values, so `HIITL_API_KEY` alone starts hybrid mode. The `HIITL_SYNC_*` settings configure the sync engine in hybrid mode, and the `HIITL_TELEMETRY_*` settings its telemetry. A set `HIITL_SYNC_*` or `HIITL_TELEMETRY_*` variable that no setting reads raises `ConfigurationError` when the client is constructed, naming the variables its family reads; a name an earlier release read (the `HIITL_SYNC_TELEMETRY_*` names) is refused naming its replacement. A variable left set is never ignored silently.

| Variable | Setting |
|----------|---------|
| `HIITL_ENVIRONMENT` | dev, stage, or prod (default: dev) |
| `HIITL_AGENT_ID` | Agent identifier (default: default) |
| `HIITL_ORG_ID` | Organization ID (must match pattern) |
| `HIITL_MODE` | OBSERVE_ALL or RESPECT_POLICY (default: OBSERVE_ALL) |
| `HIITL_POLICY_PATH` | Path to policy file (local/hybrid mode) |
| `HIITL_AUDIT_DB_PATH` | Path to SQLite database (default: ./hiitl_audit.db) |
| `HIITL_ENABLE_RATE_LIMITING` | Enable rate limiting (default: true) |
| `HIITL_ROUTES_PATH` | Path to the route config directory (optional) |
| `HIITL_SIGNATURE_KEY` | HMAC signature key (optional) |
| `HIITL_DEDUP_WINDOW_SECONDS` | A repeated idempotency key within it returns the first decision (default: 86400) |
| `HIITL_API_KEY` | API key (hybrid/hosted mode) |
| `HIITL_SERVER_URL` | Server URL (the sync target in hybrid mode; required for hosted mode) |
| `HIITL_EVALUATION` | local or remote; remote is the explicit opt-in to hosted mode (default: local) |
| `HIITL_SYNC` | false keeps a client with an api_key in pure local mode (default: true) |
| `HIITL_COLD_START_BEHAVIOR` | warn-and-observe, fail-closed, or observe-silent (default: warn-and-observe) |
| `HIITL_TIMEOUT` | HTTP timeout in seconds (hosted mode, default: 5.0) |
| `HIITL_MAX_RETRIES` | Max retry attempts (hosted mode, default: 3) |
| `HIITL_FAIL_MODE` | FAIL_CLOSED or FAIL_OPEN, what an outage answers (hosted mode, default: FAIL_CLOSED) |
| `HIITL_TELEMETRY_LEVEL` | full, standard, minimal, or off; off sends no telemetry (hybrid mode, default: standard) |
| `HIITL_TELEMETRY_INTERVAL` | Telemetry upload interval in seconds, 5 to 3600 (default: 60) |
| `HIITL_TELEMETRY_BUFFER_SIZE` | Max buffered telemetry records, 10 to 1000 (default: 60) |
| `HIITL_TELEMETRY_SAMPLE_RATE` | Fraction of evaluations whose details are counted, 0 to 1 (default: 1.0) |
| `HIITL_TELEMETRY_PARAMETER_TOOLS` | JSON list of the actions whose parameters telemetry counts (default: none) |
| `HIITL_CACHE_DIR` | Disk cache location (default: ~/.hiitl/cache/) |
| `HIITL_SYNC_AUDIT_INTERVAL` | Audit upload interval in seconds (default: 30) |
| `HIITL_SYNC_POLICY_INTERVAL` | Policy refresh interval in seconds (default: 300) |
| `HIITL_SYNC_ROUTE_INTERVAL` | Route refresh interval in seconds (default: 300) |
| `HIITL_SYNC_KS_INTERVAL` | Kill switch poll interval in seconds (default: 30) |
| `HIITL_SYNC_AUDIT_BATCH` | Max records per audit upload (default: 100) |
| `HIITL_SYNC_MAX_BUFFER` | Unsynced audit records before BUFFER_FULL (default: 10000) |
| `HIITL_SYNC_MAX_BUFFER_BYTES` | Unsynced audit bytes before BUFFER_FULL (default: 52428800) |
| `HIITL_SYNC_INIT_TIMEOUT` | Cold start sync timeout in seconds (default: 10) |
| `HIITL_SYNC_CB_THRESHOLD` | Circuit breaker failure threshold (default: 5) |
| `HIITL_SYNC_CB_RESET` | Circuit breaker reset timeout in seconds (default: 60) |
| `HIITL_SYNC_MAX_STALE` | Max cache stale age in seconds (default: 86400) |
| `HIITL_SYNC_TIMEOUT` | HTTP timeout for sync requests in seconds (default: 10.0) |
| `HIITL_SYNC_MAX_RETRIES` | Max retry attempts for sync requests (default: 3) |

```bash
export HIITL_ENVIRONMENT="prod"
export HIITL_POLICY_PATH="/etc/hiitl/policy.yaml"
```

```python
# Picks up those settings from the environment; no HIITL_API_KEY is set, so the mode is local
hiitl = HIITL(agent_id="payment-agent", mode="RESPECT_POLICY")
```

## Context manager

The HIITL client supports context manager usage to ensure resources are released:

```python
with HIITL(policy_path="./policy.yaml") as hiitl:
    decision = hiitl.evaluate("process_payment", parameters={"amount": 50})
# Resources released automatically
```

This is equivalent to calling `hiitl.close()` manually, which releases HTTP connections in hosted mode.

## Errors

| Exception | When |
|-----------|------|
| `ConfigurationError` | Invalid constructor arguments or missing required fields |
| `AuditLogError` | Audit database cannot be created or initialized |

A policy file that cannot be found, read or parsed is not raised: `evaluate()`, which reads the file, returns `POLICY_ERROR` with the cause as its reason code and logs the loader's message.

```python
from hiitl.sdk.exceptions import ConfigurationError

try:
    hiitl = HIITL(mode="RESPECT_POLICY")
except ConfigurationError as e:
    print(e)
    # "policy_path is required for RESPECT_POLICY mode.
    #
    # Provide a policy file:
    #   HIITL(policy_path='./policy.yaml', mode='RESPECT_POLICY')
    #
    # Or use OBSERVE_ALL mode (default) which works without a policy file:
    #   HIITL()
    #
    # Or use hybrid mode with an API key (policies sync from server):
    #   HIITL(api_key='sk_live_...')"
```

<Tip>
  Error messages include code examples showing how to fix the problem. This is intentional -- every error should answer "what happened?" and "what should I do about it?"
</Tip>
