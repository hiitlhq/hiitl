## Signature

```python
hiitl.evaluate(
    action: str,
    *,
    parameters: dict | None = None,
    target: dict | None = None,
    operation: str = "execute",
    user_id: str | None = None,
    session_id: str | None = None,
    agent_id: str | None = None,
    confidence: float | None = None,
    reason: str | None = None,
    sensitivity: list[Sensitivity] | None = None,
    cost_estimate: CostEstimate | None = None,
    requested_scopes: list[str] | None = None,
    idempotency_key: str | None = None,
    principal_token: str | None = None,
    correlation_id: str | None = None,
) -> Decision
```

Only `action` is required (positional). Everything else is keyword-only with sensible defaults.

## Parameters

Every numeric value, including numbers nested in `parameters`, `target` or metadata,
follows [the shared numeric domain](https://github.com/hiitlhq/hiitl/blob/main/docs/specs/sync_engine.md#numeric-domain).
A typed numeric member requires a number within its declared type and range. Where text is admitted,
pass nanosecond timestamps and smallest-unit amounts outside that domain as text;
a reached numeric condition on that text stops and blocks with
`POLICY_ERROR` / `POLICY_EVALUATION_FAILED`, unless the other conditions already
settle the rule. A refusal names the value's path.

An optional SDK argument left at its default or passed as `None` remains not given.
A null supplied inside a file, body or mapping still follows that data field's declared type; a null in open caller data remains data.

<ParamField path="action" type="str" required>
  Action name. This is the tool or operation being evaluated (e.g., `"process_payment"`, `"send_email"`, `"delete_user"`).
</ParamField>

<ParamField path="parameters" type="dict | None" default="None">
  Action parameters as a dictionary. Policy conditions can reference these via `parameters.*` field paths.

  ```python
  parameters={"amount": 150.00, "currency": "usd"}
  ```
</ParamField>

<ParamField path="target" type="dict | None" default="None">
  Target resource identifiers. Describes what the action acts on.

  ```python
  target={"account_id": "acct_123", "region": "us-east-1"}
  ```
</ParamField>

<ParamField path="operation" type="str" default='"execute"'>
  Operation type. One of: `"read"`, `"write"`, `"create"`, `"delete"`, `"execute"`, `"update"`.
</ParamField>

<ParamField path="user_id" type="str | None" default="None">
  User identifier. Used for per-user rate limiting and audit attribution.
</ParamField>

<ParamField path="session_id" type="str | None" default="None">
  Session identifier. Groups related actions for audit and debugging.
</ParamField>

<ParamField path="agent_id" type="str | None" default="None">
  Override the `agent_id` set during initialization. Useful when a single SDK instance serves multiple agents.
</ParamField>

<ParamField path="confidence" type="float | None" default="None">
  Agent confidence score between 0.0 and 1.0. Policies can use this to route low-confidence actions to human review.
</ParamField>

<ParamField path="reason" type="str | None" default="None">
  Free-text reasoning for the action. Recorded in the audit trail. Maximum 500 characters.
</ParamField>

<ParamField path="sensitivity" type="list[Sensitivity] | None" default="None">
  Sensitivity labels for the action. Values: `"money"`, `"identity"`, `"permissions"`, `"regulated"`, `"irreversible"`, `"pii"`, `"sensitive_data"`.
</ParamField>

<ParamField path="cost_estimate" type="CostEstimate | None" default="None">
  Estimated cost of the action.

  ```python
  from hiitl.core.types import CostEstimate
  cost_estimate=CostEstimate(tokens=5000, dollars=0.02)
  ```
</ParamField>

<ParamField path="requested_scopes" type="list[str] | None" default="None">
  Permission scopes this call requests — free strings your code supplies, distinct from the verified principal's scopes. A policy compares them with `principal.scopes` (e.g. block a call that requests a scope the principal was not granted).

  ```python
  requested_scopes=["refunds:write"]
  ```
</ParamField>

<ParamField path="idempotency_key" type="str | None" default="None">
  Key for one logical action, recorded in the envelope. Auto-generated if not provided. Pass the same key when you retry an action: a call under a key the audit store already holds, for an envelope within the dedup window (`dedup_window_seconds`, default 24 hours) of this one, returns the first call's decision (its `action_id` names the first action) and writes no record. The scope is the org and the environment. Two calls in flight at once under one new key, from any clients of one audit store in one process, are taken as if one came first: the second waits for the first and returns its decision. Processes that share an audit file are not held to this.
</ParamField>

<ParamField path="principal_token" type="str | None" default="None">
  A token that identifies the caller. In local and hybrid mode, the SDK passes it to the `principal_verifier` you configure and sets the envelope's `principal` from the claims it returns. A token the verifier rejects leaves `principal` unset. Without a `principal_verifier`, `evaluate()` raises `ConfigurationError`. In hosted mode, the SDK sends the token to the service, which verifies it.
</ParamField>

<ParamField path="correlation_id" type="str | None" default="None">
  Your own ID tying this action to others, such as a request ID. Recorded in the envelope as given.

  The envelope's `trace_id` is not an option. When the OpenTelemetry API (`opentelemetry-api`) is installed, the SDK sets it from the span active when you call `evaluate()`. Without the API, or outside a span, it is unset. The API is never a dependency of `hiitl`.
</ParamField>

## Returns

A [`Decision`](/sdk/python-decision) object. See the Decision reference for all fields and convenience properties.

## Examples

### Minimal call

```python
from hiitl import HIITL

hiitl = HIITL()

decision = hiitl.evaluate("send_email")
if decision.allowed:
    send_email()
```

### With parameters and target

```python
decision = hiitl.evaluate(
    "process_payment",
    parameters={"amount": 500.00, "currency": "usd"},
    target={"account_id": "acct_123"},
    operation="execute",
    user_id="user_456",
)
```

### Full call with all options

```python
from hiitl.core.types import CostEstimate, Sensitivity

decision = hiitl.evaluate(
    "deploy_infrastructure",
    parameters={
        "region": "us-east-1",
        "instance_type": "m5.xlarge",
        "count": 3,
    },
    target={"cluster_id": "prod-main"},
    operation="create",
    user_id="user_ops_lead",
    session_id="deploy-session-001",
    confidence=0.95,
    reason="Scheduled capacity increase for Black Friday",
    sensitivity=["money", "irreversible"],
    cost_estimate=CostEstimate(dollars=2.50),
    idempotency_key="deploy-bf-2025-001",
)
```

### Handling different decisions

```python
decision = hiitl.evaluate(
    "process_payment",
    parameters={"amount": 10000.00, "currency": "usd"},
)

if decision.observed:
    # OBSERVE mode — action was logged but not enforced
    print(f"Would have been: {decision.would_be}")
    process_payment()

elif decision.ok:
    # ALLOW or SANDBOX — safe to proceed
    process_payment()

elif decision.blocked:
    # BLOCK, KILL_SWITCH, or RATE_LIMIT
    print(f"Blocked: {decision.reason_codes}")
    if decision.remediation:
        print(f"Suggestion: {decision.remediation.suggestion}")

elif decision.needs_approval:
    # REQUIRE_APPROVAL, PAUSE, or ESCALATE
    print(f"Needs review: {decision.reason_codes}")
    if decision.escalation_context:
        print(f"Route to: {decision.escalation_context}")
```

Check `decision.observed` first: `decision.ok` is also `True` for `OBSERVE`.

### Observe mode awareness

In OBSERVE_ALL mode (the default), nothing is blocked, a [rate-limit rule](/concepts/policies#rate-limit-rules) included: a call past its limit returns `OBSERVE` with `would_be: RATE_LIMIT`. The decision tells you what *would* happen under enforcement:

```python
hiitl = HIITL()  # OBSERVE_ALL by default

decision = hiitl.evaluate("process_payment", parameters={"amount": 10000})

print(decision.allowed)               # True (observe mode)
print(decision.decision)              # "OBSERVE"
print(decision.observed)              # True
print(decision.would_be)              # "BLOCK" (what enforcement would do)
print(decision.would_be_reason_codes) # ["NO_MATCHING_RULE"] (no policy loaded)
```

## Errors

| Exception | When |
|-----------|------|
| `EnvelopeValidationError` | Invalid field values (e.g., confidence > 1.0): the envelope cannot be built |
| `ValueError` | `operation` is not one of the six operations |
| `ConfigurationError` | `principal_token` passed with no `principal_verifier` configured (local and hybrid mode) |
| `ServerError` | The server answers with no decision (hosted mode): a missing or unknown API key, a key without the `evaluate` scope, a body it cannot read as an envelope |

```python
from hiitl.sdk.exceptions import EnvelopeValidationError

try:
    decision = hiitl.evaluate("process_payment", confidence=5.0)
except EnvelopeValidationError as e:
    print(f"Validation failed: {e}")
    print(f"Field errors: {e.validation_errors}")
```

<Tip>
  `evaluate()` raises only before an envelope exists. Once it does, a failure is a decision with `allowed` false: `SIGNATURE_INVALID` for a signature that does not verify, `POLICY_ERROR` for a policy that cannot be loaded or evaluated, and `BLOCK` with `AUDIT_WRITE_FAILED` when the audit record cannot be written. Any other failure is `BLOCK` too: `error.code` `AUDIT_READ_FAILED` when the store cannot be read for the key's first decision, and `EVALUATION_FAILED` for the rest. Each is recorded where the store answers, and no action runs without a record. In hosted mode a service that cannot be reached is `CONTROL_PLANE_UNAVAILABLE` (with `metadata`; not allowed unless `fail_mode` is `FAIL_OPEN`), recorded in the local store and sent to the service before the next call once it answers. Do not run the action when `evaluate()` raises.
</Tip>

## Recording the result

An action's records make its lifecycle: its decision, then what happened when it ran. Once an action the decision allowed has run, record its result against the decision's `action_id`. In hosted mode the call goes to [`POST /v1/actions/{action_id}/result`](/api/evaluate#recording-the-result); in local and hybrid mode it is written to the SDK's own store, with the same refusals. The result is its own record, its content hash covering the result, and hybrid mode uploads it with the decision records.

```python
import time
from hiitl import LifecycleError

decision = hiitl.evaluate("process_payment", parameters={"amount": 150.00, "currency": "usd"})
if decision.ok:
    started = time.monotonic()
    try:
        process_payment(...)
        status, error = "succeeded", None
    except Exception as e:
        status, error = "failed", str(e)
    try:
        hiitl.record_result(decision.action_id, status, error=error,
                            duration_ms=(time.monotonic() - started) * 1000)
    except LifecycleError as e:
        print(e.reason)   # e.g. RESULT_ALREADY_RECORDED: a different result is recorded
```

`record_result(action_id, status, *, error=None, duration_ms=None)` returns the record that holds the result. In hosted mode while the service cannot be reached, it returns `{"action_id": ..., "execution_result": ..., "held": True}`: the result is held in the local store at `audit_db_path` and sent before the next call, after its decision. A store that cannot write the result raises `AuditLogError`. A result that is not recorded raises `LifecycleError`; its `reason` is one of:

| Reason | When |
|--------|------|
| `RESULT_INVALID` | `status` is not `succeeded`, `failed` or `canceled`, `error` is not a string, or `duration_ms` is not a non-negative number |
| `ACTION_NOT_FOUND` | No decision is recorded for the `action_id` in this organization and environment |
| `RESULT_ON_UNALLOWED_DECISION` | The decision did not allow the action and holds it for no review (it carries no `resume_token`), so it never ran and has no result |
| `RESULT_ALREADY_RECORDED` | A different result is already recorded for the action. Sending the same result again returns its record |

A decision held for review (it carries a `resume_token`) takes its result. The local store holds no review case, so in local and hybrid mode the record names the review it did not read, `review: {"unread": "<resume_token>"}`, and its content hash covers it. In hybrid mode the service reads the case when the record is uploaded and refuses it when the case did not let the action run; in local mode the record stands as named. In hosted mode the service reads the case when the result is sent.

The same result again returns the record that holds it, so a retry is safe.
