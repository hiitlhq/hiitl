## Signature

```typescript
hiitl.evaluate(options: EvaluateOptions): Decision | Promise<Decision>
```

In local mode, `evaluate()` returns a `Decision`, or a `Promise<Decision>` when it asks a sync route. In hybrid and hosted mode, it returns a `Promise<Decision>`. Always `await` the result:

```typescript
const decision = await hiitl.evaluate({ action: 'send_email' });
```

## Options

Only `action` is required. Everything else has sensible defaults.

```typescript
interface EvaluateOptions {
  action: string;
  operation?: Operation | string;
  target?: Record<string, unknown>;
  parameters?: Record<string, unknown>;
  user_id?: string;
  session_id?: string;
  agent_id?: string;
  confidence?: number;
  reason?: string;
  sensitivity?: Sensitivity[];
  cost_estimate?: CostEstimate;
  requested_scopes?: string[];
  idempotency_key?: string;
  principal_token?: string;
  correlation_id?: string;
}
```

`@hiitl/sdk` does not export `EvaluateOptions`. To name the type, use `Parameters<HIITL['evaluate']>[0]`.

## Parameters

Every numeric value, including numbers nested in `parameters`, `target` or metadata,
follows [the shared numeric domain](https://github.com/hiitlhq/hiitl/blob/main/docs/specs/sync_engine.md#numeric-domain).
A typed numeric member requires a number within its declared type and range. Where text is admitted,
pass nanosecond timestamps and smallest-unit amounts outside that domain as text;
a reached numeric condition on that text stops and blocks with
`POLICY_ERROR` / `POLICY_EVALUATION_FAILED`, unless the other conditions already
settle the rule. A refusal names the value's path.

<ParamField path="action" type="string" required>
  Action name. This is the tool or operation being evaluated (e.g., `"process_payment"`, `"send_email"`, `"delete_user"`).
</ParamField>

<ParamField path="parameters" type="Record<string, unknown>" default="{}">
  Action parameters as an object. Policy conditions can reference these via `parameters.*` field paths.

  ```typescript
  parameters: { amount: 150.00, currency: 'usd' }
  ```
</ParamField>

<ParamField path="target" type="Record<string, unknown>" default="{}">
  Target resource identifiers. Describes what the action acts on.

  ```typescript
  target: { account_id: 'acct_123', region: 'us-east-1' }
  ```
</ParamField>

<ParamField path="operation" type="Operation | string" default='"execute"'>
  Operation type. One of: `"read"`, `"write"`, `"create"`, `"delete"`, `"execute"`, `"update"`.
</ParamField>

<ParamField path="user_id" type="string">
  User identifier. Used for per-user rate limiting and audit attribution.
</ParamField>

<ParamField path="session_id" type="string">
  Session identifier. Groups related actions for audit and debugging.
</ParamField>

<ParamField path="agent_id" type="string">
  Override the `agent_id` set during initialization. Useful when a single SDK instance serves multiple agents.
</ParamField>

<ParamField path="confidence" type="number">
  Agent confidence score between 0 and 1. Policies can use this to route low-confidence actions to human review.
</ParamField>

<ParamField path="reason" type="string">
  Free-text reasoning for the action. Recorded in the audit trail. Maximum 500 characters.
</ParamField>

<ParamField path="sensitivity" type="Sensitivity[]">
  Sensitivity labels for the action. Values: `"money"`, `"identity"`, `"permissions"`, `"regulated"`, `"irreversible"`, `"pii"`, `"sensitive_data"`.
</ParamField>

<ParamField path="cost_estimate" type="CostEstimate">
  Estimated cost of the action: the envelope's `tokens`, `dollars` and `api_calls`. Any other key is refused with `EnvelopeValidationError`, naming it.

  ```typescript
  cost_estimate: { tokens: 5000, dollars: 0.02 }
  ```
</ParamField>

<ParamField path="requested_scopes" type="string[]">
  Permission scopes this call requests — free strings your code supplies, distinct from the verified principal's scopes. A policy compares them with `principal.scopes` (e.g. block a call that requests a scope the principal was not granted).

  ```typescript
  requested_scopes: ['refunds:write']
  ```
</ParamField>

<ParamField path="idempotency_key" type="string">
  Key for one logical action, recorded in the envelope. Auto-generated if not provided. Pass the same key when you retry an action: a call under a key the audit store already holds, for an envelope within the dedup window (`dedup_window_seconds`, default 24 hours) of this one, returns the first call's decision (its `action_id` names the first action) and writes no record. The scope is the org and the environment. Two calls in flight at once under one new key, from any clients of one audit store in one process, are taken as if one came first: the second waits for the first and returns its decision. Processes that share an audit file are not held to this.
</ParamField>

<ParamField path="principal_token" type="string">
  A token that identifies the caller. In local and hybrid mode, the SDK passes it to the `principal_verifier` you configure and sets the envelope's `principal` from the claims it returns. A token the verifier rejects leaves `principal` unset. Without a `principal_verifier`, `evaluate()` throws `ConfigurationError`. In hosted mode, the SDK sends the token to the service, which verifies it.
</ParamField>

<ParamField path="correlation_id" type="string">
  Your own ID tying this action to others, such as a request ID. Recorded in the envelope as given.

  The envelope's `trace_id` is not an option. When `@opentelemetry/api` is installed, the SDK sets it from the span active when you call `evaluate()`, through the context manager your OpenTelemetry setup registers. Without the API, or outside a span, it is unset. The API is never a dependency of `@hiitl/sdk`.
</ParamField>

## Returns

A [`Decision`](/sdk/typescript-decision) object, or a `Promise<Decision>` (see [Signature](#signature)). See the Decision reference for all fields.

## Examples

### Minimal call

```typescript
import { HIITL } from '@hiitl/sdk';

const hiitl = new HIITL();

const decision = await hiitl.evaluate({ action: 'send_email' });
if (decision.allowed) {
  await sendEmail();
}
```

### With parameters and target

```typescript
const decision = await hiitl.evaluate({
  action: 'process_payment',
  parameters: { amount: 500.00, currency: 'usd' },
  target: { account_id: 'acct_123' },
  operation: 'execute',
  user_id: 'user_456',
});
```

### Full call with all options

```typescript
const decision = await hiitl.evaluate({
  action: 'deploy_infrastructure',
  parameters: {
    region: 'us-east-1',
    instance_type: 'm5.xlarge',
    count: 3,
  },
  target: { cluster_id: 'prod-main' },
  operation: 'create',
  user_id: 'user_ops_lead',
  session_id: 'deploy-session-001',
  confidence: 0.95,
  reason: 'Scheduled capacity increase for Black Friday',
  sensitivity: ['money', 'irreversible'],
  idempotency_key: 'deploy-bf-2025-001',
});
```

### Handling different decisions

```typescript
const decision = await hiitl.evaluate({
  action: 'process_payment',
  parameters: { amount: 10000.00, currency: 'usd' },
});

if (decision.allowed) {
  // ALLOW, OBSERVE or SANDBOX — safe to proceed
  await processPayment();
} else if (['REQUIRE_APPROVAL', 'PAUSE', 'ESCALATE'].includes(decision.decision)) {
  // Needs human review
  console.log(`Needs review: ${decision.reason_codes}`);
  if (decision.escalation_context) {
    console.log('Route to:', decision.escalation_context);
  }
} else if (decision.decision === 'RATE_LIMIT') {
  // Rate limited — check when to retry
  if (decision.rate_limit) {
    console.log(`${decision.rate_limit.current}/${decision.rate_limit.limit}`);
    console.log(`Resets at: ${decision.rate_limit.reset_at}`);
  }
} else {
  // BLOCK, KILL_SWITCH, or other denial
  console.log(`Blocked: ${decision.reason_codes}`);
  if (decision.remediation) {
    console.log(`Suggestion: ${decision.remediation.suggestion}`);
  }
}
```

### Observe mode awareness

In OBSERVE_ALL mode (the default), nothing is blocked, a [rate-limit rule](/concepts/policies#rate-limit-rules) included: a call past its limit returns `OBSERVE` with `would_be: RATE_LIMIT`. The decision tells you what *would* happen under enforcement:

```typescript
const hiitl = new HIITL(); // OBSERVE_ALL by default

const decision = await hiitl.evaluate({
  action: 'process_payment',
  parameters: { amount: 10000 },
});

console.log(decision.allowed);               // true (observe mode)
console.log(decision.decision);              // "OBSERVE"
console.log(decision.would_be);              // "BLOCK"
console.log(decision.would_be_reason_codes); // ["NO_MATCHING_RULE"] (no policy loaded)
```

## Errors

| Exception | When |
|-----------|------|
| `EnvelopeValidationError` | Invalid field values (e.g., confidence > 1, or an `operation` that is not one of the six): the envelope cannot be built |
| `ConfigurationError` | `principal_token` passed with no `principal_verifier` configured (local and hybrid mode) |
| `ColdStartError` | Hybrid mode with `cold_start_behavior: 'fail-closed'`, when no policy has synced |
| `ServerError` | The server answers with no decision (hosted mode): a missing or unknown API key, a key without the `evaluate` scope, a body it cannot read as an envelope |

```typescript
import { EnvelopeValidationError } from '@hiitl/sdk';

try {
  const decision = await hiitl.evaluate({
    action: 'process_payment',
    confidence: 5.0, // Invalid: must be 0-1
  });
} catch (e) {
  if (e instanceof EnvelopeValidationError) {
    console.error('Validation failed:', e.message);
    console.error('Field errors:', e.validation_errors);
  }
}
```

<Tip>
  `evaluate()` throws only before an envelope exists. Once it does, a failure is a decision with `allowed` false: `SIGNATURE_INVALID` for a signature that does not verify, `POLICY_ERROR` for a policy that cannot be loaded or evaluated, and `BLOCK` with `AUDIT_WRITE_FAILED` when the audit record cannot be written. Any other failure is `BLOCK` too: `error.code` `AUDIT_READ_FAILED` when the store cannot be read for the key's first decision, and `EVALUATION_FAILED` for the rest. Each is recorded where the store answers, and no action runs without a record. In hosted mode a service that cannot be reached is `CONTROL_PLANE_UNAVAILABLE` (with `metadata`; not allowed unless `fail_mode` is `FAIL_OPEN`), recorded in the local store and sent to the service before the next call once it answers. Do not run the action when `evaluate()` throws.
</Tip>

## Recording the result

An action's records make its lifecycle: its decision, then what happened when it ran. Once an action the decision allowed has run, record its result against the decision's `action_id`. In hosted mode the call goes to [`POST /v1/actions/{action_id}/result`](/api/evaluate#recording-the-result); in local and hybrid mode it is written to the SDK's own store, with the same refusals. The result is its own record, its content hash covering the result, and hybrid mode uploads it with the decision records.

```typescript
import { LifecycleError } from '@hiitl/sdk';

const decision = await hiitl.evaluate({ action: 'process_payment', parameters: { amount: 150.0, currency: 'usd' } });
if (decision.allowed) {
  const started = performance.now();
  let status = 'succeeded';
  let error: string | undefined;
  try {
    await processPayment(/* … */);
  } catch (e) {
    status = 'failed';
    error = String(e);
  }
  try {
    await hiitl.recordResult(decision.action_id, status, { error, duration_ms: performance.now() - started });
  } catch (e) {
    if (e instanceof LifecycleError) console.log(e.reason); // e.g. RESULT_ALREADY_RECORDED: a different result is recorded
  }
}
```

`recordResult(action_id, status, { error?, duration_ms? })` resolves to the record that holds the result. In hosted mode while the service cannot be reached, it resolves to `{ action_id, execution_result, held: true }`: the result is held in the local store at `audit_db_path` and sent before the next call, after its decision. A store that cannot write the result throws `AuditLogError`. A result that is not recorded throws `LifecycleError`; its `reason` is one of:

| Reason | When |
|--------|------|
| `RESULT_INVALID` | `status` is not `succeeded`, `failed` or `canceled`, `error` is not a string, or `duration_ms` is not a non-negative number |
| `ACTION_NOT_FOUND` | No decision is recorded for the `action_id` in this organization and environment |
| `RESULT_ON_UNALLOWED_DECISION` | The decision did not allow the action and holds it for no review (it carries no `resume_token`), so it never ran and has no result |
| `RESULT_ALREADY_RECORDED` | A different result is already recorded for the action. Sending the same result again returns its record |

A decision held for review (it carries a `resume_token`) takes its result. The local store holds no review case, so in local and hybrid mode the record names the review it did not read, `review: {"unread": "<resume_token>"}`, and its content hash covers it. In hybrid mode the service reads the case when the record is uploaded and refuses it when the case did not let the action run; in local mode the record stands as named. In hosted mode the service reads the case when the result is sent.

The same result again returns the record that holds it, so a retry is safe.
